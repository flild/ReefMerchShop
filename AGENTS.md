│# Контекст проекта «РИФ» (Reef)

Этот файл содержит всю ключевую информацию о проекте, чтобы нейросети (и другие разработчики) могли быстро понять структуру, стек и бизнес-логику приложения.

## О проекте



**Название:** РИФ (Reef)

**Слоган:** Типография для мерчеделов / Твоя гавань мерча

**Целевая аудитория:** Художники, иллюстраторы и авторы, заказывающие печать своего мерча (акриловые брелоки, стенды, значки и т.д.).

**Основная цель сайта:** Упростить процесс расчета, заказа и подготовки макетов к печати. Снизить нагрузку на менеджеров и создать удобную экосистему для авторов.

## Технологический стек



* **Фреймворк:** Next.js 15+ (App Router)


* **Язык:** TypeScript


* **Стилизация:** Tailwind CSS v4 (подключен через `@import "tailwindcss"` в `globals.css`)


* **База данных:** SQLite (локальный файл `local.db` для разработки, подключение через `libsql/client`)


* **ORM:** Drizzle ORM


* **Иконки:** `lucide-react`

* **Анимации:** `motion/react` (Framer Motion) + Tailwind CSS + кастомные классы


* **Уведомления:** `sonner`

## Дизайн-система и UI/UX (Критически важно!)



Сайт выполнен в стилистике, близкой к аниме/манге, с элементами "поп-арта".

* Толстые обводки: Классы `.anime-border` (жирная темная граница) применяются почти ко всем интерактивным карточкам и инпутам.


* Резкие тени: Класс `.anime-shadow` (резкая смещенная тень без размытия, например, `4px 4px 0px #0f172a`).


* Скругления: Используются сильные скругления `rounded-[32px]`, `rounded-[40px]`, `rounded-full`.


* Цветовая палитра:


* `reef-blue`: Основной темно-синий/индиго.


* `reef-cyan`: Ярко-голубой акцентный цвет.


* `reef-light`: Очень светлый, почти белый цвет фона секций.


* Желтый цвет для кнопок и акцентов (например, `bg-yellow-400`).




* Паттерны: Используется класс `.manga-dots` для фоновых точек в стиле скринтонов из манги.


* Общий тон: Дружелюбный, креативный, неформальный. Обращение к пользователю на "ты" или "вы", но в творческой манере.



## Структура Базы Данных (Drizzle ORM)



Схема описана в `src/db/schema.ts`.

* `users`: Пользователи (клиенты, персонал) с привязками Telegram и VK.


* `files`: Единый реестр файлов (макеты, цветопробы). В БД хранятся метаданные и пути.


* `material_types`: Системные типы материалов (`acrylic`, `wood`, `holography` и т.д.).


* `categories` и `material_categories`: Категории витрины и складских материалов.


* `portfolioItems`: Примеры готовых работ для витрины.


* `materials`, `blanks` и `accessories`: Складские остатки акрила, заготовок и фурнитуры. `materials` привязаны к `material_types` через `type_id`.


* `orders`, `order_items`, `order_status_history`: Нормализованная структура заказов и резервов.


* `order_proofs`: Цветопробы по заказам с системой утверждения.


* `collects` и `collect_participants`: Совместные закупки и участники с макетами и тиражами.


* `articles`: Статьи и обучающие гайды.


* `templates` и `checklist_rules`: Шаблоны для скачивания и правила предпечатных проверок.



## Работа с файлами (Object Storage)



* Изображения портфолио, пользовательские макеты (`PSD`, `AI`) и фотографии цветопроб **никогда не хранятся в БД**.


* В SQLite (таблица `files`) лежат только метаданные: ID, оригинальное имя, MIME-тип и путь/URL к файлу.


* Физически файлы загружаются в S3-совместимое хранилище (или локальную директорию `uploads` на этапе MVP).



## Основные разделы приложения (`src/app/`)



1. **`/` (Главная страница)**: Презентация типографии, инструменты, последние работы, материалы, отзывы и FAQ.


2. **`/calculator`**: Калькулятор стоимости заказа с учетом тиража, материала и фурнитуры.


3. **`/collects`**: Каталог совместных заказов и запись на участие.


4. **`/materials`**: Каталог материалов с динамической группировкой по типам.


5. **`/portfolio`**: Галерея выполненных заказов по категориям.


6. **`/profile`**: Личный кабинет (история заказов, прикрепленные макеты, настройки).


7. **`/admin`**: Админ-панель (заказы, склад, коллекты, контент, пользователи).


8. **`/tools/mockup`**: Онлайн-генератор мокапов изделий.


9. **`/tools/check`**: Автоматическая проверка файлов макетов.


10. **`/tools/checklist`**: Интерактивная памятка для подготовки файлов.


11. **`/guides`**: Обучающие материалы и статьи для художников.

## Правила для ИИ (AI Instructions)



* **Модульность:** Разделяй крупные файлы на логические компоненты, избегай монолитных компонентов на 500+ строк.


* **Server Components по умолчанию:** Добавляй `'use client'` только там, где требуются хуки состояния (`useState`, `useEffect`), анимации `motion` или обработчики событий.


* **Оптимизация изображений:** Никогда не используй сырой `<img>`. Всегда применяй `<Image>` из `next/image` с обязательными `alt`, `fill` или явными `width`/`height`.


* **Строгая типизация:** Никаких `any`. Все интерфейсы сущностей и формы должны быть строго описаны через TypeScript-типы и Zod-схемы.


* **Сохранение стиля:** Все интерактивные элементы оформляются через семантические классы `.anime-border`, `.anime-shadow`, `.anime-button`.


* **Работа с БД (SQLite):** Использовать `drizzle-orm/sqlite-core`, соблюдать внешние ключи и режимы каскадного удаления.


* **Server Actions для мутаций:** Все изменения в БД осуществляются исключительно через Server Actions (`'use server'`) в директории `src/actions/`. Не создавать API-маршруты в `src/app/api/`, кроме вебхуков (S3, Telegram, эквайринг, СДЭК).


* **Семантические токены вместо `dark:`:** В React-компонентах запрещено использовать префикс `dark:`. Использовать семантические классы:


* Фоны: `bg-theme-bg`, `bg-theme-surface`.


* Текст: `text-theme-text`, `text-theme-muted`.


* Границы: `border-theme-border`.


* Акценты: `text-theme-highlight`, `bg-theme-accent`.


* Статусы: `bg-theme-green-bg`, `text-theme-green-text`, `bg-theme-yellow-bg`, `text-theme-yellow-text`.





### SEO-метаданные



* **Шаблонизация Title:** Корневой layout задает `title: { template: '%s | Reef', default: '...' }`. Во вложенных страницах экспортировать только короткое имя (`title: 'Калькулятор'`) без ручного дописывания бренда.


* **Динамические метаданные (`generateMetadata`):** Для динамических сущностей (материалы, коллекты, статьи) формировать метаданные и `og:image` на основе данных из БД.


* **Канонические ссылки:** Указывать абсолютный `canonical` URL во всех динамических страницах.


* **Хлебные крошки:** Страницы глубже первого уровня обязаны содержать навигационную цепочку и невидимый JSON-LD со схемой `BreadcrumbList`.



### Авторизация и ролевая модель (Auth & RBAC)



Роли в системе: `client`, `maker` (макетчица), `manager`, `admin`.

* **Кастомный JWT:** Авторизация на связке `jose` (HS256) + `bcryptjs` без внешних библиотек (NextAuth/Lucia). Токен хранится в защищенной куке `session` (`HttpOnly`, `SameSite: Lax`). Payload: `{ userId, role }`.


* **Edge Guard (`src/middleware.ts`):** Маршрутизация на уровне Edge. Неавторизованные отправляются в `/login`, клиенты при заходе в `/admin` — в `/profile`. Доступ макетчицы (`maker`) к закрытым разделам (`/admin/users`, `/admin/content`, `/admin/portfolio`) глухо пресекается редиректом в `/admin/orders`.


* **Изоляция в Server Components:** Данные фильтруются на сервере через `getSession()` из `@/lib/auth`.


* **Ограничения роли `maker` (Критически важно!):**
* **Заказы (`/admin/orders`):** Полностью скрыты финансовые поля (`total`, `price`). Кнопки создания, редактирования и удаления исключены из DOM.
* **Коллекты (`/admin/collects`):** Полностью скрыты касса сбора (`currentSum`), таргет (`targetSumLimit`), скидка и суммы взносов участников (`totalPrice`). Заблокирован доступ к экранам создания, редактирования и добавления участников. Разрешены просмотр тиражей (`quantity`), контактов, ссылок на макеты и смену производственных статусов.
* **Склад (`/admin/inventory`):** Заблокированы редактирование остатков, удаление и редактирование системных типов.
* **Навигация:** Из `AdminSidebar` для `maker` исключены пункты «Пользователи», «Контент» и «Портфолио».


* **Защита Server Actions:** Каждое серверное действие валидирует сессию (`assertStaff` или `assertStaffManager`). Скрытие кнопок в UI обязательно дублируется проверкой на бэкенде.



### Валидация данных (Validation & Zod)



* Единый стандарт валидации входных данных — **Zod**.


* Схемы валидации изолированы в директории `src/lib/validations/`.
* Запрещено прямое доверие `formData.get()` или приведению типов (`as string`, `Number(...)`). Все входящие данные Server Actions обязаны парситься через `schema.safeParse()`.



### Уведомления и обработка ошибок (Toast Notifications)



* Стандарт уведомлений проекта — **Sonner** (`toast` из `sonner`).
* Нативный браузерный `alert()` запрещен.
* Результаты выполнения Server Actions (`{ success, error }`) обрабатываются на клиенте через всплывающие тосты `toast.success(...)` и `toast.error(...)`.
