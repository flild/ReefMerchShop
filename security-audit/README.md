# Аудит безопасности Reef — 12 ноября 2026

Проверен локальный проект на основе `48168f0`. Этот отчёт сопровождает исправления и результаты локальных проверок; публикация не выполнялась. Рабочие `local.db` и `sqlite.db` не использовались для атак и тестовых мутаций.

## Найденные проблемы и исправления

| Проблема | Риск до исправления | Результат |
| --- | --- | --- |
| Действия заказов, портфолио, категорий, статей и чек-листов не проверяли сессию | Высокий: прямой вызов зарегистрированного Server Action мог обойти ограничения интерфейса; действия выполняли мутации без проверки пользователя | Добавлены серверные проверки `assertStaff`, `assertStaffManager`, `assertAdmin`; закрытые страницы также проверяют права перед чтением данных |
| При отсутствии `JWT_SECRET` использовался известный ключ из исходников | Критический при такой конфигурации: подделка административной сессии | Общий ключ удалён; подпись требует настроенного секрета от 32 символов; проверяются алгоритм, issuer, audience, срок и структура payload |
| Роль из JWT оставалась действующей семь дней после понижения или удаления пользователя | Высокий: бывший администратор мог продолжать административные действия | Каждый серверный запрос сессии проверяет существование пользователя и его текущую роль в БД |
| Формы создания и редактирования заказа получали `select *` из users | Высокий: менеджер получал хеши паролей всех пользователей в props клиентского компонента | Передаются только `id`, `name`, `email`; отсутствие хешей проверено в production HTTP/RSC-ответе |
| Для maker скрывали суммы в DOM, сохраняя `totalPrice` в props; dashboard показывал выручку | Средний: утечка закрытых финансов | В props maker передаётся `null`; финансовый dashboard требует manager/admin; проверено отсутствие тестовой суммы в HTTP/RSC-ответе |
| Загрузки доверяли расширению и содержимому файла | Высокий: запись HTML/SVG в публичную директорию, риск активного содержимого на домене приложения | Единая проверка размера до 5 МБ и декодирование через исправленную sharp; принимаются JPEG/PNG/WebP, результат перекодируется в JPEG; UUID имени не зависит от имени файла |
| Цветопробы сохранялись в public | Средний: файл по известной ссылке не проверял владельца заказа | Новые файлы сохраняются в `uploads/proofs` вне public; `/files/[id]` проверяет сотрудника или владельца заказа; старые `/uploads/proofs/*` блокируются middleware |
| Редактор и список статей находились по публичным `/content/articles` | Высокий: доступ к черновикам и полному тексту редактора без авторизации | Редактор перенесён в `/admin/content/articles`, старые адреса перенаправляют; middleware и страницы проверяют права; гостю/client/maker доступ закрыт |
| Вход и регистрация не имели серверной Zod-валидации и ограничения попыток | Средний: перебор паролей, некорректные и чрезмерные входные данные | Добавлены схемы, нормализация email, ограничения длины и минимальная длина нового пароля 8 символов; квоты хранятся в SQLite и общие для процессов |
| Production-cookie могла не иметь Secure при отсутствующем APP_URL | Средний: риск передачи сессии по HTTP | В production Secure включён независимо от APP_URL; HttpOnly и SameSite=Lax сохранены |
| JSON-LD вставлял JSON без экранирования `<` | Высокий при контроле данных разметки: выход из script через `</script>` | `<` заменяется на `\u003c`; проверено вредоносным названием |
| Статусы принимали произвольные строки; maker мог выставлять платёжные статусы | Средний: обход рабочего процесса | Добавлены допустимые статусы; maker не может выставить paid/pending_payment или редактировать заявку; изменение участника привязано к collectId, удаление позиции — к orderId; при загрузке проверяется принадлежность позиции заказу |
| Перенаправления доверяли x-forwarded-host/proto | Низкий, зависит от конфигурации прокси | Прямое доверие этим заголовкам удалено; используются APP_URL или origin запроса |
| Уязвимые версии библиотек | Отказ в обслуживании и условные RCE в зависимости от платформы и используемых возможностей | Обновлены Next.js, React, sharp, Zod и транзитивные библиотеки; production npm audit: 0 |

Middleware служит предварительной проверкой JWT. Решение о доступе к данным и мутациям принимается на сервере по текущему пользователю БД. Отдельные проверки страниц нужны и при изменении роли уже после выдачи токена.

## Зависимости

Установлены и согласованы в npm/Bun lock-файлах: Next.js **15.5.29**, React/React DOM **19.2.9**, sharp **0.35.5**, Zod **4.6.7**, PostCSS **8.5.32**. Overrides PostCSS и qs закрывают уязвимые вложенные версии без перехода Next.js на другую основную версию.

До исправления `npm audit --omit=dev`: **14 пакетов с advisories** — 3 critical, 7 high, 4 moderate. После исправления: **0**. Число пакетов с advisories не является числом подтверждённых способов эксплуатации приложения.

Полная проверка дерева, включая devDependencies: **27 moderate**, high/critical — **0**. Остаток относится к инструментам разработки и их транзитивным зависимостям: OpenTelemetry core, esbuild из esbuild-kit, glob/minimatch, postcss-selector-parser, uuid. Reachability этих advisories в процессе разработки отдельно не доказывалась. Автоматические рекомендации npm включают несовместимые переходы и понижения основных версий; они не применялись. Не следует считать полное дерево зависимостей полностью очищенным.

Первичные источники для проверки зависимостей:

- [Next.js: обновление безопасности от 14 октября 2026](https://nextjs.org/blog/nextjs-security-update-october-14-2026): исправления DoS Server Actions и условных RCE; наличие версии в уязвимом диапазоне само по себе не доказывает достижимость каждой RCE в Reef.
- [Next.js: RCE на Windows](https://github.com/vercel/next.js/security/advisories/GHSA-p293-qw3h-jr36): исходная установленная 15.5.23 входила в диапазон до 15.5.24; ОС сервера публикации не проверялась.
- [Next.js: защита данных и Server Actions](https://nextjs.org/docs/app/guides/data-security): авторизация действий и минимальные данные клиентских компонентов.

## Проверки

Выполнены:

- `npm run test:security`: **16 групп проверок** исходных модулей с временной SQLite и настоящей sharp. Проверяются роли, отсутствие пользователя, подделка JWT, понижение роли, мутации, props, запрет активных файлов, приватные цветопробы, конкурентная квота, JSON-LD, регистрация/вход и гостевые заявки в коллекты. Файловая тестовая БД нужна для проверки транзакций libsql и удаляется после прогона.
- `node security-audit/http-smoke.cjs`: **6 HTTP-проверок** настоящей production-сборки на localhost с временной тестовой БД. Проверены редиректы, роли, хеши паролей в RSC, скрытые цены, черновики, блокировка старых файловых URL, заголовки и поддельный JWT. Временный сервер и БД удалены после проверки.
- `npm run build`, `tsc --noEmit --incremental false`, ESLint изменённых TypeScript-файлов и `git diff --check`.
- `npm audit --omit=dev` и полный `npm audit`.

Модульный стенд перехватывает файловые записи и Next request/cache/navigation. Его успешный результат не подменяет HTTP-проверку. Исторические результаты первоначального воспроизведения сохранены отдельно в `probe-results.json`; текущие — в `regression-results.json` и `http-results.json`.

Не проверялись опубликованный сервер, конфигурация reverse proxy/S3, сетевые TLS-настройки, внешние бэкапы, логи возможных прошлых атак и нагрузочная устойчивость. Аудит не устанавливает, эксплуатировались ли проблемы ранее.

## Настройка при публикации

1. Задать отдельный случайный `JWT_SECRET` минимум 32 символа в окружении сервера. Локальный секрет создан в игнорируемом `.env.local`; его значение не выводилось и не добавлено в Git. Не переносить этот локальный ключ в репозиторий.
2. Задать настоящий HTTPS `APP_URL`. Production-cookie требует HTTPS. После замены ключа и формата JWT старые сессии потребуют повторного входа.
3. Обеспечить постоянное хранилище для приватной `uploads/` и публичных изображений. Таблица `security_rate_limits` создаётся при первом запросе ограничиваемого действия; существующие пользовательские данные не переписываются.
4. Если старые цветопробы дополнительно раздаются отдельным static-сервером или CDN, закрыть `/uploads/proofs/*` и там: middleware приложения не управляет внешним хранилищем.
